# QII One Vault — خزنة ملاحظات خاصة (Supabase + RLS)

مشروع تجريبي تعليمي من **QII One**: تسجيل دخول حقيقي لمستخدمين، وكل مستخدم يملك
ملاحظات خاصة لا يستطيع أي مستخدم آخر قراءتها — العزل مفروض على مستوى قاعدة
البيانات نفسها عبر **Row Level Security (RLS)** في Supabase (PostgreSQL).

## المكونات

| الملف | الوظيفة |
|---|---|
| `index.html` | صفحة تعريفية للمشروع |
| `app.html` | التطبيق: تسجيل الدخول/الحساب الجديد + إدارة الملاحظات |
| `assets/js/config.js` | رابط المشروع والمفتاح العام (anon) — **لا مفاتيح سرية** |
| `assets/js/vault.js` | منطق المصادقة والقراءة والكتابة وفحص العزل |
| `supabase/schema.sql` | جدول `notes` + تفعيل RLS + سياسة `auth.uid() = user_id` |
| `assets/css/vault.css` | تنسيق بهوية QII (كحلي/أبيض/رمادي + أخضر وبرتقالي) |

## خطوات التشغيل

### 1) إنشاء مشروع Supabase
1. سجّل الدخول إلى <https://supabase.com/dashboard>.
2. **New Project** — اختر اسم المشروع (مثل `qii-one-vault`)، وحدّد كلمة مرور لقاعدة البيانات، وأنطقة المشروع (أقرب منطقة للمستخدمين).
3. انتظر حتى تكتمل التجهيزات (دقيقة تقريباً).

### 2) تفعيل RLS وبناء الجدول
1. من الداشبورد افتح **SQL Editor**.
2. افتح محتوى الملف `supabase/schema.sql`، انسخه كاملاً، الصقه، واضغط **Run**.
3. تحقق من ظهور الجدول `notes` في **Table Editor** مع علامة **RLS enabled**.

ملخص ما ينفذه المخطط:
- جدول `notes` مع عمود `user_id` افتراضي `auth.uid()`.
- `alter table ... enable row level security`.
- سياسة واحدة: `using (auth.uid() = user_id) with check (auth.uid() = user_id)` — تغطي القراءة والإدراج والتحديث والحذف.

### 3) ربط الواجهة
1. من **Project Settings → API** انسخ:
   - **Project URL** → ضعه في `assets/js/config.js` مكان `YOUR_SUPABASE_URL`.
   - **anon / publishable key** → ضعه مكان `YOUR_SUPABASE_ANON_KEY`.
2. المفتاح العام (anon) مخصص أصلاً للنشر في المتصفح؛ حمايته تتم عبر RLS.
   أما مفتاح **service_role** فهو سري ولا يُستخدم في هذا المشروع نهائياً.

### 4) إنشاء مستخدمين اثنين على الأقل
طريقتان:

**أ) من داخل التطبيق (موصى به للاختبار):**
1. من **Authentication → Providers → Email** أوقف خيار *Confirm email* مؤقتاً.
2. افتح `app.html`، من تبويب «حساب جديد» أنشئ: `user1@example.com` ثم `user2@example.com` (كل كلمة مرور 6 أحرف فأكثر).

**ب) يدوياً من الداشبورد:**
من **Authentication → Users → Add user** أضف بريدين وكلمات مرور.

### 5) اختبار العزل (تحقق من RLS)
1. سجّل الدخول بـ **user1**، أضف ملاحظتين (مثلاً «ملاحظات المستخدم الأول»).
2. سجّل الخروج، ثم سجّل الدخول بـ **user2**:
   - يجب أن تظهر القائمة **فارغة تماماً** رغم وجود ملاحظات user1.
   - اضغط زر **«افحص العزل (RLS)»**: يجب أن يعرض
     `✅ RLS يعمل: ترى N صفوف، وعدد الصفوف التي تخص مستخدمين آخرين = 0.`
3. ارجع بـ **user1**: تظهر ملاحظاتك كما هي دون تغيير.

لماذا هذا دليل حقيقي؟ لأن الاستعلام في `vault.js` يتم بدون أي فلتر
`where user_id = ...` من جهة الكود — قاعدة البيانات نفسها تُخفي الصفوف
الغير مملوكة بفضل السياسة، حتى لو عدّلت الواجهة أو حاول أي حساب الاستعلام مباشرة.

## تشغيل محلي
افتح `index.html`/`app.html` من خادم محلي (أي سيرفر ثابت)، مثل:

```powershell
# من داخل مجلد المشروع (Windows: py بدل python)
py -m http.server 8080
# ثم افتح http://localhost:8080
```

أو ارفع الملفات إلى GitHub Pages كما في موقع QII One الرئيسي.

## ملاحظات أمنية
- لا يحتوي المشروع على أي مفتاح سري؛ `config.js` يحمل الرابط والمفتاح العام فقط.
- الحماية الحقيقية هي سياسات RLS في `supabase/schema.sql`.
- لا تُستخدم خدمة `service_role` من المتصفح إطلاقاً.
